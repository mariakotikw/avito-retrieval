# Avito Retrieval Bootcamp

Решение задачи retrieval из Avito Data Science Bootcamp. Для каждого поискового
запроса необходимо вернуть не более 50 релевантных объявлений. Итоговый файл
отправки находится в [`answer.csv`](answer.csv).

Контрольный локальный `Recall@50` финального ранжировщика: **0.873028**. Метрика
получена на отложенных поисковых группах, а не на строках, случайно смешанных с
обучающими примерами.

## Данные

Исходные файлы нужно разместить в каталоге `data/`:

- `train.parquet` — история соответствий запросов и выбранных объявлений;
- `benchmark_queries.parquet` — запросы, для которых строится ответ;
- `benchmark_items.parquet` — доступный каталог объявлений.

`data/` не хранится в Git из-за размера и условий распространения датасета.
Код использует следующие группы полей:

- текст запроса и объявления: `search_query`, `search_infm_params_text`,
  `item_title_raw`, `item_infm_params_text`, `item_description_raw`;
- рубрикация: `search_category`, `item_category_id`, `item_microcat_id`;
- география и доставка: `search_location_id`, `item_location_id`,
  `search_is_delivery_search`;
- качество и цена объявления: `item_rating`, `item_rating_reviews_count`,
  `item_price`;
- история взаимодействий: частоты пар запрос–микрокатегория,
  запрос–география и популярность `item_id`.

Текстовые поля отвечают за смысловое совпадение. Категория, микрокатегория и
география резко уменьшают число нерелевантных кандидатов. Поведенческие частоты
нужны для неоднозначных и коротких запросов, а цена, рейтинг и популярность
помогают упорядочить лексически близкие объявления.

## Алгоритм

Решение состоит из генерации кандидатов и финального ранжирования.

1. Текст приводится к нижнему регистру, `ё` заменяется на `е`, пунктуация
   удаляется, пробелы нормализуются.
2. Word TF-IDF по униграммам и биграммам ищет точные совпадения слов и фраз.
   Character TF-IDF по `char_wb`-граммам длины 3–5 устойчив к опечаткам,
   словоформам и различному написанию моделей товара.
3. Из `train.parquet` строится поведенческое расширение текста объявления:
   частые запросы добавляются к объявлениям с тем же заголовком и
   микрокатегорией.
4. Для каждого запроса предсказываются пять вероятных микрокатегорий. Кандидаты
   ищутся несколькими независимыми каналами: по всему каталогу, внутри
   микрокатегории, в точной локации и в исторически связанных локациях.
5. Точные и близкие запросы из истории образуют отдельный candidate channel.
   Ранжирования word/character каналов объединяются через Reciprocal Rank
   Fusion.
6. Итоговый `LightGBM LGBMRanker` с objective `lambdarank` выбирает top-50 из
   объединения кандидатов.

Для LambdaRank используются:

- наличие кандидата, позиция и reciprocal rank в каждом retrieval-канале;
- совпадение категории и локации, позиция предсказанной микрокатегории;
- `P(microcategory | query)`, `P(microcategory | query + params)` и
  `P(item_location | search_location, category)` из истории;
- доли пересечения токенов запроса с заголовком и параметрами;
- точное вхождение запроса и совпадение токенов с цифрами;
- логарифмы цены, числа отзывов, частоты запроса и популярности объявления;
- рейтинг объявления.

Параметры модели и все случайные разбиения зафиксированы через
`random_state=42`.

## Проверка качества

Локальная проверка повторяет retrieval-сценарий:

- строки `train.parquet` делятся `GroupShuffleSplit` по полной сигнатуре запроса
  (`текст + локация + доставка + параметры + категория`);
- 18% уникальных поисковых групп откладываются, поэтому одинаковый запрос не
  попадает одновременно в обучение и валидацию;
- для быстрой и воспроизводимой оценки фиксированно выбираются 1000 запросов с
  `random_state=42`;
- сначала измеряется покрытие релевантных объектов объединением candidate
  channels, затем `Recall@50` после ранжирования;
- LambdaRank обучается на 800 локальных запросах и проверяется на оставшихся
  200, после чего для финального ответа переобучается на всех 1000.

`src/validate_answer.py` дополнительно проверяет число строк, уникальность
`query_id`, длину top-50, отсутствие повторов и существование каждого `item_id`
в benchmark-каталоге.

## Анализ ошибок

В ходе локальных экспериментов обнаружились пять основных групп ошибок:

- **Глобальный TF-IDF смешивал рубрики и города.** Добавлены отдельные
  microcategory/local/geo retrieval-каналы и маршруты между исторически
  связанными локациями.
- **Word TF-IDF пропускал опечатки, словоформы и варианты написания.** Добавлен
  character TF-IDF, а каналы объединены через RRF.
- **Короткие и неоднозначные запросы попадали не в ту микрокатегорию.** Вместо
  одного жёсткого класса используются top-5 микрокатегорий, вероятности из
  истории и обучаемый ранжировщик.
- **Похожие исторические запросы иногда вытесняли хорошие новые кандидаты.** В
  финальном ответе жёсткая квота из истории применяется только к запросам с
  точной исторической сигнатурой; остальные исторические кандидаты оценивает
  LambdaRank.
- **Модели товара с разными числами выглядели лексически похожими.** Добавлены
  признаки совпадения и конфликта числовых токенов.

Эти изменения направлены не на перестановку уже найденных документов, а прежде
всего на увеличение candidate recall, который задаёт верхнюю границу итогового
`Recall@50`.

## Воспроизведение

Рекомендуемая среда: Python 3.11 или 3.12, Windows/Linux x86-64. Версии
библиотек зафиксированы в `requirements.txt`.

```bash
python -m venv .venv
python -m pip install -r requirements.txt
python src/reproduce.py --output answer.csv
```

`reproduce.py` последовательно создаёт все benchmark- и local-кэши, обучает
финальный LambdaRank, записывает `answer.csv` и запускает проверку результата.
Промежуточные файлы сохраняются в `cache/` и `artifacts/`; оба каталога
исключены из Git. Первый полный запуск требует значительных ресурсов CPU и
может занять длительное время, повторный использует кэш.

SHA-256 опубликованного `answer.csv`:

```text
1a1479a2657929a524f61b632bfe63d9264bfec63a91b4d2521a306828ad2a4d
```

Различие только в переводах строк между Windows и Linux может изменить
побайтовую SHA-256, не меняя таблицу и порядок рекомендаций.

Для запуска отдельных диагностических этапов:

```bash
python src/eda.py
python src/eval_v4_local.py --queries 1000
python src/eval_stratified_local.py --queries 1000
python src/run_v8_ranker.py --local-only
python src/validate_answer.py answer.csv
```

В Git Bash на Windows при проблемах с выводом кириллицы используйте префикс
`PYTHONIOENCODING=utf-8`. В PowerShell задайте
`$env:PYTHONIOENCODING='utf-8'`.
